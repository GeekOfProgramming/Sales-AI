## 2. Phase 1 — Cloudflare Neuron Accounting Corrections

### 2.1 The Accounting Defect in S3.5.5A
In S3.5.5A, the Neuron conversion constants for `@cf/meta/llama-3.1-8b-instruct-fp8` were derived backwards from published rounded USD token prices:
- Published Input: $0.152 / 1M tokens $\rightarrow \frac{0.152}{0.000011} \approx 13,818.18$ Neurons
- Published Output: $0.287 / 1M tokens $\rightarrow \frac{0.287}{0.000011} \approx 26,090.91$ Neurons

However, official Cloudflare documentation establishes that Workers AI computes billing using **exact native Neuron rates**, while the USD prices are rounded commercial-equivalent references:
- **Official Input Rate:** **13,778 Neurons / 1M tokens** ($0.013778$ Neurons/token)
- **Official Output Rate:** **26,128 Neurons / 1M tokens** ($0.026128$ Neurons/token)
- **Neuron Unit Price:** $0.011 / 1,000 Neurons ($0.000011 / Neuron)
- **Mathematical Check:**
  $$13,778 \times \$0.000011 = \$0.151558 \approx \$0.152 \text{ / 1M tokens}$$
  $$26,128 \times \$0.000011 = \$0.287408 \approx \$0.287 \text{ / 1M tokens}$$

### 2.2 Code Implementation in `cloudflare_provider.py`
The inaccurate inverse-price constants were replaced with authoritative constants:
```python
CLOUDFLARE_FP8_NEURONS_PER_1M_INPUT = 13778.0
CLOUDFLARE_FP8_NEURONS_PER_1M_OUTPUT = 26128.0
CLOUDFLARE_NEURON_UNIT_COST_USD = 0.000011
CLOUDFLARE_DAILY_FREE_NEURONS = 10000.0

CLOUDFLARE_FP8_PUBLISHED_INPUT_USD_PER_1M = 0.152
CLOUDFLARE_FP8_PUBLISHED_OUTPUT_USD_PER_1M = 0.287
```

### 2.3 Exact vs Conservative Rounding Analysis
We explicitly resolved the code/documentation mismatch regarding fractional vs ceiling operations:

1. **Exact Fractional Neurons (`estimate_cloudflare_neurons_exact`):**
   $$\text{Neurons}_{\text{exact}} = \left(\frac{\text{input\_tokens}}{1\,000\,000} \times 13\,778.0\right) + \left(\frac{\text{output\_tokens}}{1\,000\,000} \times 26\,128.0\right)$$
   Used for usage telemetry, metrics, and exact conversion.

2. **Conservative Preflight Integer Reservation (`estimate_cloudflare_neurons_preflight`):**
   $$\text{Neurons}_{\text{preflight}} = \lceil\text{in\_neurons}\rceil + \lceil\text{out\_neurons}\rceil$$
   Applying ceiling per-component guarantees:
   - $\lceil a \rceil + \lceil b \rceil \ge \lceil a + b \rceil$
   - Neither the input prompt nor the generated output is ever under-reserved.
   - For output-heavy tasks (such as website extraction pass_a generating 1,024 tokens from a short prompt), per-component ceiling prevents budget overrun.

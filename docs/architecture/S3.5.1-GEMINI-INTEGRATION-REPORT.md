## 1. Executive Summary & Acceptance Corrections

In accordance with S3.5.1 acceptance criteria, the following corrections have been implemented and verified:

1. **Critical Pricing Correction:**
   - Updated the rate card for `gemini-3.5-flash-lite` to match Google Gemini API official Standard Paid Tier pricing:
     - **Input:** `$0.30 / 1M tokens`
     - **Output (including thinking tokens):** `$2.50 / 1M tokens`
     - **Source:** [https://ai.google.dev/gemini-api/docs/pricing](https://ai.google.dev/gemini-api/docs/pricing)
   - Preflight reservations, conservative spending liability accounting, and cost estimates now use these corrected bounds.
   - Maintained separation between Free Tier (`currency="FREE"`, actual invoice cost `$0.000000`) and conservative preflight liability accounting.

2. **HTTP Error Taxonomy Disambiguation:**
   - **HTTP 400:** Categorized strictly as `LLMInvalidRequestError` (`error_code="INVALID_REQUEST"`, invalid request parameters or malformed arguments). Removed incorrect classification as schema error.
   - **HTTP 401:** Categorized as `LLMAuthenticationError` (`error_code="AUTH_ERROR"`, invalid or missing credentials).
   - **HTTP 403:** Categorized as `LLMPermissionError` (`error_code="PERMISSION_DENIED"`, permission denied, unauthorized access).
   - **HTTP 404:** Categorized as `LLMNotFoundError` (`error_code="NOT_FOUND"`, model or endpoint path not found).
   - **HTTP 429:** Disambiguated between quota exhaustion (`LLMQuotaExceededError`) and transient rate limits (`LLMRateLimitError`).
   - **HTTP 5xx:** Categorized as `LLMProviderUnavailableError` (upstream provider failure, `retryable=True`).
   - **Output Schema Errors:** Retained strictly for downstream output validation failures (`LLMInvalidSchemaError`, model response failing JSON syntax or Pydantic/contract schema validation after successful HTTP transport).

3. **Gemini 2.5 Root-Cause Evidence Status:**
   - Evaluated the previous `gemini-2.5-flash-lite` HTTP 404 failure against the successful `gemini-3.5-flash-lite` inference.
   - The exact endpoint was `https://generativelanguage.googleapis.com/v1beta/openai/chat/completions`.
   - Although metadata probes to model catalogs may return HTTP 200, the chat completions endpoint returned HTTP 404.
   - Because live network probing is prohibited during development and internal Google routing details cannot be queried live, the definitive cause for `gemini-2.5-flash-lite` unreachability is classified as **UNRESOLVED (model ID unrouted or deprecated on v1beta/openai)** rather than confirmed unavailable globally.

4. **Candidate Mappings & Accounting:**
   - `t1_c2` remains strictly bound to `gemini-2.5-flash-lite`.
   - `t1_c5` maps to `gemini-3.5-flash-lite`.
   - Historical reservation `res_dce87e9ce2a9` (`gemini-2.5-flash-lite`, `UNCERTAIN`, liability `$0.000634`) in `data/benchmark_budget.db` remains untouched.
   - Smoke tests remain strictly bounded (`SMOKE_ONLY / NOT MODEL-QUALIFIED`) and cannot authorize production routes.

## 4. HTTP Error Taxonomy Hardening

The gateway exception hierarchy in `sales_engine/llm_gateway/errors.py` and adapter parsing in `openai_provider.py` / `cohere_provider.py` now enforce distinct error classes:

```
LLMError
├── LLMNotConfiguredError (404 / unconfigured)
├── LLMInvalidRequestError (HTTP 400 - bad arguments, invalid parameters)
├── LLMAuthenticationError (HTTP 401 - bad / missing API key)
│   └── LLMPermissionError (HTTP 403 - permission denied, forbidden)
├── LLMNotFoundError (HTTP 404 - model or path not found)
├── LLMTimeoutError (transport timeout)
├── LLMRateLimitError (HTTP 429 - transient request rate limit)
├── LLMQuotaExceededError (HTTP 429 - credits/quota exhausted)
├── LLMBudgetExceededError (local budget limit reached)
├── LLMInvalidSchemaError (post-transport model output schema validation failure)
└── LLMProviderUnavailableError (HTTP 5xx - upstream outage)
```

**Key Distinction:** `LLMInvalidSchemaError` is exclusively reserved for model output parsing failures (e.g. malformed JSON or schema non-conformance returned with HTTP 200). HTTP 400 errors from the provider transport are strictly classified as `LLMInvalidRequestError`.

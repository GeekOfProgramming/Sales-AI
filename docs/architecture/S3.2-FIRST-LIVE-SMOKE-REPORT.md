## 1. Executive Summary

SalesAI S3.2 addresses and resolves the three critical paid-execution blockers identified during independent review of S3.1, enabling safe, auditable, and bounded live smoke testing of an external Tier-1 model without risking uncontrolled spending, mock leakage, or broken ledger accounting.

Key accomplishments:
1. **Real Provider Wiring (LIVE-01 Resolved):** In live mode (`--live --confirm-paid`), `ExternalBenchmarkRunner` registers the real HTTPS `OpenAIProvider` adapter for one verified Tier-1 slot (`t1_c1`, `gpt-6-luna`). Mock providers (`openai_compatible_mock`) and fictitious pricing models (`pricing.mock.internal`) are strictly prohibited and refused. The remaining 15 candidate slots remain explicitly disabled.
2. **Strict Limit Enforcement (LIVE-02 Resolved):** User-specified `--max-requests` (positive integer between 1 and 20) and `--max-cost-usd` (positive finite float between 0.0 and 1.00) are rigorously validated on initialization. Dispatches are intercepted and blocked if the request ceiling is reached, or if conservative preflight spending projections exceed the remaining per-run allowance.
3. **Persistent SQLite Ledger & Auditable Runbook (LIVE-03 Resolved):** Live execution strictly rejects ephemeral in-memory databases (`:memory:`), defaulting to a persistent, locally excluded database (`data/benchmark_budget.db`). Operator audit commands are corrected to target the actual database schema (`llm_reservations`).
4. **Offline Verification via MockTransport:** All live-mode adapter features, request formatting, token parsing, cost reconciliation, and crash/timeout handling have been verified offline with `httpx.MockTransport` without making external network calls.
5. **Quality Distinction Maintained (QUALITY-01):** Single-case smoke runs are strictly tagged `SMOKE_ONLY / NOT MODEL-QUALIFIED` and cannot approve production routes. Incomplete golden answer coverage on three task paths is documented as a known limitation for later full quality benchmarking.

## 2. Resolution of Paid-Execution Blockers

### LIVE-01: Mock-Only Provider Wiring
- **Defect in S3.1:** `ExternalBenchmarkRunner` unconditionally registered `openai_compatible_mock` and mapped candidates to mock pricing (`pricing.mock.internal`). The CLI could not reach real models, and running `--live` failed on mock pricing checks.
- **S3.2 Correction:**
  - Added `_configure_live_candidate("t1_c1")` which instantiates `OpenAIProvider` with `api_key` and optional custom transport.
  - Candidate `t1_c1` is assigned official model `gpt-6-luna`, provider `openai`, and rate card `TIER1_LIVE_LUNA_PRICING`.
  - Candidates `t1_c2`, `t1_c3`, and `t1_c4` remain disabled until their adapters and rate cards are explicitly verified in future tasks.
  - Live mode strictly requires `--candidate t1_c1` and a single explicit `--task`.

### LIVE-02: Unenforced Per-Run Limits & Ceiling Checks
- **Defect in S3.1:** `--max-requests` and `--max-cost-usd` were validated only against loose outer bounds (20 and $1.00), but `max_requests=0` or `max_cost_usd=0.0` were accepted, and neither parameter was checked before outbound dispatch.
- **S3.2 Correction:**
  - Added strict parameter validation in `ExternalBenchmarkRunner.__init__`:
    - `max_requests` must be an integer where `1 <= max_requests <= 20`. Zero, negative, float, and non-integer inputs raise `LLMBudgetExceededError`.
    - `max_cost_usd` must be a positive finite float where `0.0 < max_cost_usd <= 1.00`. Zero, negative, NaN, Inf, and overflow values raise `LLMBudgetExceededError`.
  - Preflight request ceiling check: `if self._attempted_requests_count >= self.max_requests`, the case is blocked and recorded with category `RUN_REQUEST_CAP_REACHED`.
  - Preflight conservative cost check: Calculates projected spend using maximum possible output tokens (`max_completion_tokens` or `max_output_tokens`) and conservative character-to-token ratio. If projected single-request spend or cumulative run spend exceeds `max_cost_usd`, dispatch is refused immediately with `LLMBudgetExceededError`.

### LIVE-03: Inaccurate SQLite Runbook & Memory DB Default
- **Defect in S3.1:** Default DB path was `:memory:`, meaning reservations vanished upon process exit. The published runbook referenced a nonexistent database (`sales_engine/llm_gateway/budget_ledger.db`), nonexistent table (`ledger_records`), and wrong column names (`actual_cost_usd`).
- **S3.2 Correction:**
  - In live mode (`dry_run=False`), `:memory:` is rejected with `LLMNotConfiguredError`.
  - Default database path is set to `data/benchmark_budget.db`, which is ignored in `.gitignore`.
  - Added `--db-path` CLI option in `scripts/benchmark_external_llm.py`.
  - Created `docs/architecture/S3.2-LIVE-SMOKE-RUNBOOK.md` with accurate PowerShell commands querying table `llm_reservations` and columns `reservation_id, request_id, model, status, reserved_usd, final_cost_usd`.

## 4. Known Benchmark Limitations (QUALITY-01)

As documented in `sales_engine/benchmark/report_s3.py` and required by S3.2:

1. **Incomplete Golden Answer Coverage:** While 70 synthetic fixture cases exist across the 7 task/subtask paths, reference answers (`expected_output`) are currently populated only for `website_extraction:pass_a`, `website_extraction:pass_b`, `job_analysis`, and `lead_scoring`. The remaining paths (`discovery_query_generation`, `reply_suggestion`, `outreach_draft`) currently evaluate syntactic and schema validity, but lack full ground-truth semantic scoring.
2. **Smoke Test Boundary:** A 1-case smoke run verifies network connectivity, adapter translation, authentication, and budget ledger mechanics. It **DOES NOT** constitute model qualification or production approval. Recommendations retain `status: "SMOKE_ONLY" / NOT MODEL-QUALIFIED` and `is_production_approved: False`.

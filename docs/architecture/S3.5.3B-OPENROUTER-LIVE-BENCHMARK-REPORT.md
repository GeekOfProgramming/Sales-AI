## 3. Fail-Closed Free-Only Routing & Fallback Hardening

### 3.1 Problem Statement: Fallback Leakage
OpenRouter features a multi-provider fallback routing mechanism: if an upstream provider fails or rate limits, OpenRouter can automatically route the prompt to a secondary provider or paid fallback if configured. Furthermore, clients can provide a `models: [...]` array. In automated benchmarking, this could lead to:
1. Silent redirection to a non-free or paid provider variant.
2. Inaccurate benchmark attribution (evaluating model B while reporting model A).
3. Financial liability on an unmonitored account.

### 3.2 Implemented Architectural Protections

1. **Explicit Provider Fallback Prohibition:**
   In [sales_engine/llm_gateway/providers/openai_provider.py](file:///c:/Sales-AI/SalesAI/sales_engine/llm_gateway/providers/openai_provider.py), the payload builder explicitly injects OpenRouter's provider routing constraint:
   ```python
   # Explicitly disable OpenRouter fallback to prevent silent routing to paid variants
   if self._provider_id == "openrouter" or cap.get("provider_fallbacks") is False:
       payload["provider"] = {"allow_fallbacks": False}
   ```
2. **Single Model Enforcement:**
   Only the exact `model: "google/gemma-4-26b-a4b-it:free"` parameter is serialized. No fallback array (`models`) is passed.
3. **Free-Tier Allowlist Validation:**
   In [sales_engine/benchmark/provider_catalog.py](file:///c:/Sales-AI/SalesAI/sales_engine/benchmark/provider_catalog.py), `classify_model_billing` requires both inclusion in `EXPLICIT_VERIFIED_FREE_MODELS["openrouter"]` and the `:free` suffix. Any model missing the suffix is classified as `VERIFIED_PAID`.
4. **Dynamic Preflight Check in Runner:**
   In [sales_engine/benchmark/external_runner.py](file:///c:/Sales-AI/SalesAI/sales_engine/benchmark/external_runner.py), `--free-only` preflight checks verify that `spec.input_price_per_1m == 0.0` and `spec.output_price_per_1m == 0.0` in addition to classification.
5. **Generation Enabled Gate:**
   Attempting live generation against a candidate with `is_generation_enabled=False` (such as historical `t2_c1`) raises `GatewayDispatchError` with failure code `GENERATION_DISABLED`.

1. **Account State:** The operator's account has 50 daily free requests remaining (0 used). The key limit is active and unblocked.

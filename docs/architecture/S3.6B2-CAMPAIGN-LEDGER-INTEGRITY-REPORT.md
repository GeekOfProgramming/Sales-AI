## Executive Summary & Go/No-Go Recommendation

During independent verification of S3.6B.1, several critical financial-safety and concurrency defects were discovered in the campaign ledger system (`sales_engine/benchmark/external_runner.py`). Specifically:
1. `cancel(req_id, reason=...)` raised `TypeError` at runtime due to an API signature mismatch.
2. Network dispatch errors (HTTP 429, HTTP 500, timeouts) were treated as cancellations, allowing 35 consecutive failed attempts under one campaign to bypass the 10-request candidate ceiling.
3. Uncertain reservations (`is_uncertain=True`) with missing usage or zero actual costs were overwritten with `$0.00`, releasing reserved liability while remote usage remained possible.
4. Input validation allowed negative numbers, `NaN`, infinity, and non-numeric values in cost caps and reservation requests.
5. Concurrency relied on an in-memory Python `threading.Lock`, lacking true multi-process transaction safety across separate Python processes.
6. Benchmark reports omitted the campaign ID and exact SQLite ledger path.
7. Proposed CLI invocations omitted required technical gates (`--confirm-paid`, `--max-requests 10`).

All defects have been completely resolved and proven offline through `tests/test_s3_6b2_campaign_ledger_integrity.py` (20 passed tests, 0 failed) and full repository regressions (1,521 passed tests, 0 failed).

### Explicit Go/No-Go Recommendation
**RECOMMENDATION FOR S3.6C:** **GO (CONDITIONAL ON TECHNICAL LIVE GATES)**  
All campaign financial-safety gates, multi-process SQLite transactions, and conservative liability protections are verified and durable. Live execution must strictly utilize the corrected CLI commands with zero real spend permitted.

## 1. Confirmed Defects & Root Causes

| Defect ID | Description | Root Cause | Fix Applied |
| :--- | :--- | :--- | :--- |
| **DEF-01** | `TypeError: CampaignBudgetGuard.cancel() got an unexpected keyword argument 'reason'` | `CampaignBudgetGuard.cancel()` accepted only `request_id: str`, while `ExternalBenchmarkRunner` invoked `self.campaign_guard.cancel(req_id, reason=str(e))` | Updated signature to `cancel(self, request_id: str, reason: str = "") -> None`, sanitizing reason to max 200 chars and persisting in DB. |
| **DEF-02** | 35 failed attempts bypassed 10-request candidate ceiling | Any failure in network dispatch called `cancel()`, setting status to `CANCELLED`. Request count queries checked `status != 'CANCELLED'`, releasing ceiling on HTTP errors. | Introduced `DISPATCH_ATTEMPTED` and `DISPATCH_FAILED`. Network errors now call `mark_failed()`, preserving the record in `DISPATCH_FAILED` status which strictly counts towards the 10-request ceiling. Only pre-dispatch aborts transition to `PRE_DISPATCH_CANCELLED`. |
| **DEF-03** | Uncertain financial liability zeroed out | In `reconcile()`, passing `0.0` or missing usage when `is_uncertain=True` overwrote existing reservation with `$0.00`, releasing liability while provider charges were unknown. | In `reconcile()`, if `is_uncertain=True`, the guard preserves conservative reserved liability ceilings: `commercial_cost = max(existing_comm, actual_comm)` and `billable_cost = max(existing_bill, actual_bill)`. |
| **DEF-04** | Negative, NaN, inf, and boolean values accepted | Missing input validation on constructor and `check_and_reserve()` arguments. | Strict type and numeric validation (`_validate_spend_amount`) rejecting booleans, non-numbers, NaN, infinity, and negative values. Exact boundary comparison with 1e-9 tolerance. |
| **DEF-05** | Lack of multi-process atomicity | Reliance on `threading.Lock()` inside Python process; SQLite transactions lacked explicit write lock acquisition prior to count and spend summation. | Implemented `autocommit` connection mode (`isolation_level=None`) with explicit `BEGIN IMMEDIATE;` write transaction enclosing count check, ceiling check, and insertion. Rollback on any exception. |
| **DEF-06** | Report metadata missing campaign scope | `BenchmarkRunReport` lacked `campaign_id` and `ledger_db_path` attributes, preventing audit traceability. | Added `campaign_id` and `ledger_db_path` to `BenchmarkRunReport`, JSON export, and Markdown report header block. |
| **DEF-07** | Proposed CLI commands missing required live gates | Proposed commands lacked `--confirm-paid` and `--max-requests 10`, leading to command rejection (Exit code 2) or default cap of 1 request. | Corrected CLI proposals for Gemini, Groq, and Cohere. |

## 2. Campaign State Machine & Lifecycle Transitions

```
                    +-----------------------+
                    |     check_and_reserve |
                    +-----------+-----------+
                                |
                                v
                       +----------------+
                       |    RESERVED    |
                       +---+--------+---+
          Pre-dispatch     |        |   record_dispatch_attempt
          Abort / Config   |        |   (before network call)
                           v        v
  +------------------------+        +---------------------+
  | PRE_DISPATCH_CANCELLED |        | DISPATCH_ATTEMPTED  |
  +------------------------+        +---+---------+---+---+
  (Released from limits)                |         |   |
                                        |         |   |
                  Network Error / 429   |         |   | Response Received
                  (HTTP 429, 500, auth) |         |   | (Token usage present)
                                        |         |   |
                                        v         |   v
                             +-----------------+  |  +----------------+
                             | DISPATCH_FAILED |  |  |   RECONCILED   |
                             +-----------------+  |  +----------------+
                             (Counts to limit)    |  (Counts to limit & spend)
                                                  |
                         Timeout / Missing Usage  |
                         (Uncertain remote cost)  |
                                                  v
                                         +-----------------+
                                         |    UNCERTAIN    |
                                         +-----------------+
                                         (Counts to limit &
                                          holds conservative
                                          spend liability)
```

### Transition Rules
1. **`RESERVED` -> `PRE_DISPATCH_CANCELLED`**:
   - Allowed **only** before network dispatch (e.g. gateway config errors, budget blocked).
   - Releases candidate request count and financial exposure.
   - Requires sanitized `cancellation_reason`.
2. **`RESERVED` -> `DISPATCH_ATTEMPTED`**:
   - Must be written atomically before submitting HTTP request to network transport.
   - Once dispatched, cancellation is **strictly forbidden**.
3. **`DISPATCH_ATTEMPTED` -> `DISPATCH_FAILED`**:
   - Occurs on transport errors, connection timeouts, HTTP 429, HTTP 500, or HTTP 401/403 where no uncertain inference occurred.
   - **MUST** count toward candidate request ceiling (max 10).
4. **`DISPATCH_ATTEMPTED` -> `UNCERTAIN`**:
   - Occurs on read timeouts or responses missing token usage where remote provider inference may have executed.
   - Counts toward candidate request ceiling (max 10) AND **retains conservative reserved liability**.
5. **`DISPATCH_ATTEMPTED` -> `RECONCILED`**:
   - Occurs upon receipt of valid output and usage metadata.
   - Terminal state; silent transition from `UNCERTAIN` to `RECONCILED` is rejected.

## 3. Request-Count Invariants & Ceilings

The campaign ledger enforces three immutable invariants under SQLite `BEGIN IMMEDIATE`:
1. **Candidate Ceiling**:
   ```sql
   SELECT COUNT(*) FROM llm_campaign_ledger
   WHERE campaign_id = ? AND candidate_id = ?
     AND status NOT IN ('PRE_DISPATCH_CANCELLED', 'CANCELLED');
   ```
   **Constraint:** Must be `< 10` before insertion. (Max 10 requests per candidate).
2. **Campaign Aggregate Ceiling**:
   ```sql
   SELECT COUNT(*) FROM llm_campaign_ledger
   WHERE campaign_id = ?
     AND status NOT IN ('PRE_DISPATCH_CANCELLED', 'CANCELLED');
   ```
   **Constraint:** Must be `< 30` before insertion. (Max 30 aggregate requests across 3 candidates).
3. **Financial Exposure Ceiling**:
   ```sql
   SELECT COALESCE(SUM(commercial_cost_usd), 0.0), COALESCE(SUM(billable_cost_usd), 0.0)
   FROM llm_campaign_ledger
   WHERE campaign_id = ?
     AND status IN ('RESERVED', 'DISPATCH_ATTEMPTED', 'DISPATCH_FAILED', 'RECONCILED', 'UNCERTAIN');
   ```
   **Constraint:** `tot_comm + comm_spend <= commercial_cost_cap_usd` ($0.15 default) and `tot_bill + bill_spend <= billable_cost_cap_usd` ($0.05 default).

## 4. Multi-Process Atomicity & Concurrency Proof

### Concurrency Architecture
- Explicit `autocommit` mode (`sqlite3.connect(..., isolation_level=None)`).
- Write operations acquire an immediate exclusive reserved lock using `BEGIN IMMEDIATE;`.
- WAL mode (`PRAGMA journal_mode=WAL;`) with 15-second busy timeout (`PRAGMA busy_timeout=15000;`).
- Read-check-reserve is completely executed inside the write transaction prior to `COMMIT;`.

### Concurrency Verification
Validated in `tests/test_s3_6b2_campaign_ledger_integrity.py`:
- **Test 13 (`test_multiprocess_request_count_race`)**: 25 concurrent worker processes launched simultaneously against a single SQLite database attempting reservations for `t1_c5`.
  - **Result:** Exactly 10 reservations succeeded (`SUCCESS`), 15 were rejected (`BUDGET_EXCEEDED`).
  - Database row count verified: exactly 10.
- **Test 14 (`test_multiprocess_aggregate_commercial_budget_race`)**: 10 concurrent processes with commercial cap `$0.030` and `$0.008` spend per request.
  - **Result:** Exactly 3 reservations succeeded ($0.024 <= $0.030), 7 were rejected.
  - Database verified: `$0.024` total commercial spend.
- **Test 15 (`test_multiprocess_billable_budget_race`)**: 8 concurrent processes with billable cap `$0.010` and `$0.004` spend per request.
  - **Result:** Exactly 2 reservations succeeded ($0.008 <= $0.010), 6 were rejected.
  - Database verified: `$0.008` total billable spend.

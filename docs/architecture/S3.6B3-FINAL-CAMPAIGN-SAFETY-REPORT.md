## Defect Resolutions & Independent Verifications

### Defect 1 — HTTP Errors & Ambiguous Failures Incorrectly Released Commercial and Billable Liabilities
- **Root Cause:** In S3.6B.2, `CampaignBudgetGuard.mark_failed()` unconditionally reset `commercial_cost_usd = 0.0` and `billable_cost_usd = 0.0`, zeroing liabilities on dispatched requests regardless of whether provider-side processing or billing had occurred.
- **Before Resolution:**
  - Before HTTP 500: commercial reserve `$0.012000`, billable reserve `$0.005000`.
  - After `mark_failed()`: commercial `$0.000000`, billable `$0.000000`.
- **After Resolution:**
  - Dispatched requests (`DISPATCH_ATTEMPTED`) failing with ambiguous errors (HTTP 500, read timeouts, interrupted streams, server disconnects) transition to `UNCERTAIN` and preserve their conservative liability ceiling (never zeroed out).
  - Prior `UNCERTAIN` liabilities are never silently erased or reduced.
  - Confirmed nonbillable rejections (e.g., HTTP 429 rate limit before token processing, HTTP 401/403 authorization rejections) transition to `DISPATCH_FAILED` with zeroed financial cost while still counting against the campaign and candidate request caps.
  - Calling `mark_failed()` on an un-dispatched `RESERVED` record without explicit `pre_dispatch_cancellation=True` fails closed with `LLMNotConfiguredError`.
- **Evidence:** Verified by `test_defect1_http_500_preserves_conservative_liability`, `test_defect1_http_429_confirmed_nonbillable_rejection`, `test_defect1_read_timeout_and_interrupted_response`, and `test_defect1_mark_failed_on_undispatched_reserved_record_fails_closed`.

### Defect 2 — Missing Financial Estimates Silently Became Zero
- **Root Cause:** `check_and_reserve()` allowed missing estimates by falling back to `0.0`. Additionally, `reconcile()` transitioned dispatched requests into `RECONCILED` even when actual costs and token usage evidence were never supplied.
- **Before Resolution:**
  - Calling `check_and_reserve()` with missing spend resulted in `RESERVED` with costs `$0.000000`.
  - Dispatched and reconciled without evidence, transitioning to `RECONCILED` at `$0.000000`.
- **After Resolution:**
  - Missing or undefined commercial reservation estimates are strictly rejected with `LLMBudgetExceededError`.
  - Missing billable estimates are strictly rejected unless verified entitlement context applies.
  - `reconcile()` requires verified actual token usage evidence (`input_tokens`, `output_tokens`) or explicit actual non-null costs before accepting `RECONCILED`.
  - If usage evidence is missing after dispatch, `reconcile()` transitions the record to `UNCERTAIN` and retains the conservative reserved cost liability.
- **Evidence:** Verified by `test_defect2_missing_reservation_cost_rejected`, `test_defect2_missing_reconciliation_usage_retains_uncertain`, and `test_defect2_zero_charge_entitlement_validation`.

### Defect 3 — Persistent Campaign Policy Was Mutable Across Processes
- **Root Cause:** Campaign budget ceilings were only stored in Python instance attributes and were not persisted in a dedicated policy table, allowing another process opening the same campaign ID in SQLite to specify higher budget ceilings.
- **Before Resolution:**
  - Campaign A initialized with commercial cap `$0.03`.
  - A second process opening Campaign A with cap `$0.15` bypassed the original ceiling and accepted new spend.
- **After Resolution:**
  - Added dedicated persistent table `llm_campaign_policy` with primary key `campaign_id`.
  - Binds campaign ID to immutable approved candidates, per-candidate request caps, total request cap, commercial budget, billable budget, and policy version.
  - Initialized atomically under `BEGIN IMMEDIATE;`.
  - Later initializations reject any expansion or unauthorized alteration of approved candidates or cost ceilings.
  - Reconnecting processes inherit the stored policy if parameters are omitted.
- **Evidence:** Verified across separate OS worker processes by `test_defect3_conflicting_campaign_policy_across_processes_rejected` and `test_defect3_policy_persists_table_and_bounds_reconnection`.

### Defect 4 — Pre-dispatch Gateway Errors Caused Invalid Cancellation
- **Root Cause:** In `ExternalBenchmarkRunner._execute_single_case`, `record_dispatch_attempt(req_id)` was called prior to Gateway execution. If pre-network validation (such as candidate task authorization or provider routing) failed, `cancel(req_id)` was called on a record in status `DISPATCH_ATTEMPTED`, causing a secondary exception: `Cannot cancel request in status 'DISPATCH_ATTEMPTED'`.
- **Before Resolution:**
  - Mocked Gateway configuration error resulted in secondary crash inside the error handler.
- **After Resolution:**
  - Separated pre-network validation checks (candidate binding, provider resolution, task authorization) from actual network transmission.
  - `CampaignBudgetGuard.cancel()` supports `allow_pre_network=True` for pre-dispatch failures, safely recording `PRE_DISPATCH_CANCELLED` and preserving the original underlying error without masking it with a cancellation exception.
  - Dispatched requests across the network wire strictly cannot be cancelled.
- **Evidence:** Verified by `test_defect4_pre_network_gateway_refusal_cancelled_safely` and `test_defect4_dispatched_request_cannot_be_silently_cancelled`.

### Defect 5 — Duplicate Request IDs Accepted Across Campaigns
- **Root Cause:** The duplicate check in `check_and_reserve()` matched only `request_id`, candidate, and cost amounts, without verifying `campaign_id`.
- **Before Resolution:**
  - Campaign A reserved `req_dup`.
  - Campaign B reserved `req_dup` with matching candidate and amounts, succeeding without inserting a Campaign B record.
- **After Resolution:**
  - In `check_and_reserve()`, the lookup selects `campaign_id`. If the request ID is already registered under a different campaign, it fails closed with `LLMDuplicateRequestError` ("Cross-campaign request ID reuse is strictly forbidden").
  - Identical duplicate within the same campaign returns idempotently without re-dispatching.
- **Evidence:** Verified by `test_defect5_cross_campaign_request_id_collision_fails_closed` and `test_defect5_idempotent_duplicate_cannot_cause_second_dispatch`.

### Defect 6 — Historical Liabilities Were Not Integrated into Live Preflight
- **Root Cause:** `read_only_historical_liability_preflight()` existed in test fixtures but was never invoked in active runner or CLI startup paths.
- **Before Resolution:**
  - Historical liabilities in `data/benchmark_budget.db` were uninspected during runner startup.
- **After Resolution:**
  - `ExternalBenchmarkRunner.__init__` executes `read_only_historical_liability_preflight("data/benchmark_budget.db")` read-only.
  - If the database is missing or unreadable in live mode targeting default operational storage, it fails closed.
  - Historical exposure summary is attached to `BenchmarkRunReport`, displayed during CLI startup in `scripts/benchmark_external_llm.py`, and recorded in JSON and Markdown report outputs.
  - Historical operational ledger remains completely untouched (SHA-256 verified unchanged).
- **Evidence:** Verified by `test_defect6_historical_ledger_preflight_integration` and `test_defect6_historical_preflight_missing_db`.

### Defect 7 — Reporting Parity & Conservative Budget Documentation
- **Root Cause:** Default campaign ceilings ($0.15 commercial / $0.05 billable) did not document the conservative 30-case baseline ($0.035831) or clarify that zero billable spend is strictly bound to verified Free/Trial entitlements.
- **Before Resolution:**
  - Reports lacked uncertain liability totals, historical ledger exposure, and explicit safety margin documentation.
- **After Resolution:**
  - Documented the conservative 30-case baseline of `$0.035831` (10 cases each for Gemini, Groq, Cohere) with a 4.18x safety margin against runaways.
  - Added `uncertain_liability_usd`, `transport_failures_count`, `rate_limit_failures_count`, and `historical_liability` to JSON, CSV, and Markdown exports.
  - Guaranteed multi-format parity across JSON, CSV, and Markdown.
- **Evidence:** Verified by `test_defect7_reporting_parity_json_csv_markdown`.

## Exact SQLite Schema Transitions

### 1. `llm_campaign_policy` Table (New)
```sql
CREATE TABLE IF NOT EXISTS llm_campaign_policy (
    campaign_id TEXT PRIMARY KEY,
    created_at TEXT NOT NULL,
    policy_version TEXT NOT NULL,
    commercial_cost_cap_usd REAL NOT NULL,
    billable_cost_cap_usd REAL NOT NULL,
    max_requests_per_candidate INTEGER NOT NULL,
    max_total_requests INTEGER NOT NULL,
    approved_candidates TEXT NOT NULL
);
```

### 2. `llm_campaign_ledger` Table (Preserved & Enhanced)
```sql
CREATE TABLE IF NOT EXISTS llm_campaign_ledger (
    campaign_id TEXT NOT NULL,
    candidate_id TEXT NOT NULL,
    request_id TEXT PRIMARY KEY,
    run_id TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT,
    commercial_cost_usd REAL NOT NULL,
    billable_cost_usd REAL NOT NULL,
    status TEXT NOT NULL,
    cancellation_reason TEXT,
    failure_reason TEXT
);
CREATE INDEX IF NOT EXISTS idx_campaign_candidate ON llm_campaign_ledger(campaign_id, candidate_id);
```

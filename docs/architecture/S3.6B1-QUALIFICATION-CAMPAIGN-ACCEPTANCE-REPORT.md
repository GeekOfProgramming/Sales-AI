## 1. Root-Cause Analysis for Reproduced Defects

### Defect 1: CLI Pacing Integration Failure
- **Symptom:** Independent execution of `python scripts/benchmark_external_llm.py --inter-request-delay 2.5` failed with:
  ```text
  error: unrecognized arguments: --inter-request-delay 2.5
  Exit code: 2
  ```
- **Root Cause:** In S3.6B, `inter_request_delay_seconds` was implemented inside `ExternalBenchmarkRunner`, but the CLI argument `--inter-request-delay` was never registered in `parse_args()` in `scripts/benchmark_external_llm.py`, nor propagated to runner instantiation.
- **Resolution:**
  - Added `--inter-request-delay` to `argparse` in `scripts/benchmark_external_llm.py` with strict numeric validation ($0.0 \le \text{delay} \le 10.0$, rejecting negatives, NaN, Inf, and non-numeric types).
  - Wired `inter_request_delay_seconds=args.inter_request_delay` to `ExternalBenchmarkRunner`.
  - Enforced that sleeper pacing occurs between requests but **never sleeps after the final request**.

### Defect 2: Disqualified Candidates Recommended as Winners
- **Symptom:** In an evaluation run of 10 planned fixtures where 8 were attempted/evaluable and 8 passed (80% pass rate) but 2 cases remained unattempted, `summary.qualified=False`, yet `run_benchmark()` emitted:
  ```json
  "status": "PROPOSED_RECOMMENDATION"
  ```
- **Root Cause:** `run_benchmark()` checked only `meets_threshold = (safety_violations == 0 and overall_pass_rate >= 0.8)`, completely ignoring `summary.qualified` and `summary.task_qualification_eligible`.
- **Resolution:**
  - Hardened recommendation logic: candidate can **never** receive `PROPOSED_RECOMMENDATION` unless `summary.task_qualification_eligible and summary.qualified`.
  - Disqualified candidates with incomplete evaluations are explicitly marked:
    ```json
    "status": "INCOMPLETE / NOT QUALIFIED"
    ```
  - `stop_on_first_qualifying` will only stop subsequent candidate evaluation if the candidate is **actually qualified**.

### Defect 3: Inferred Dispatch Counters vs. Explicit Lifecycle
- **Symptom:** Code used `cases_evaluated = requests_attempted`, conflating attempted network dispatches with genuinely evaluable model outputs. Pre-dispatch budget blocks and request cap blocks were improperly tallied or conflated with attempted dispatches.
- **Root Cause:** Absence of a formal state machine for test case lifecycle tracking.
- **Resolution:**
  - Introduced `CaseLifecycleStatus` enum:
    - `NOT_ATTEMPTED`
    - `PRE_DISPATCH_BLOCKED`
    - `DISPATCH_ATTEMPTED`
    - `RESPONSE_RECEIVED`
    - `EVALUATED`
    - `DISPATCH_FAILED`
  - Invariant enforcement:
    - $\text{requests\_attempted} \le \text{cases\_planned}$
    - $\text{responses\_received} \le \text{requests\_attempted}$
    - $\text{cases\_evaluable} \le \text{responses\_received}$
    - $\text{cases\_evaluated} = \text{cases\_evaluable}$
    - Pre-dispatch blocks (`PRE_DISPATCH_BLOCKED`) do not increment `requests_attempted`.

### Defect 4: Incomplete Evaluation Permitted When Cases Planned > 10
- **Symptom:** The runner verified `cases_evaluable < 10`, but if 12 cases were planned and only 10 evaluated, it failed to disqualify the partial run.
- **Root Cause:** Static threshold check against `10` instead of requiring $\text{cases\_evaluable} == \text{cases\_planned}$.
- **Resolution:**
  - Enforced exact qualification equality:
    ```python
    cases_planned >= 10
    cases_evaluable == cases_planned
    requests_attempted == cases_planned
    unattempted_cases == 0
    safety_violations_count == 0
    overall_pass_rate >= qualification_threshold
    ```

### Defect 5: Uncontrolled Looping on Unrecoverable Provider Errors
- **Symptom:** When a provider returned HTTP 429 quota exhaustion or HTTP 401 authentication error, the runner attempted all 10 fixtures sequentially instead of failing closed.
- **Root Cause:** Absence of early-stop break condition on provider-level terminal failures.
- **Resolution:**
  - Added fail-closed early-stop condition on HTTP 429 quota exhaustion, HTTP 401/403 credentials, unverified entitlement, and billing errors.
  - All remaining fixtures in the campaign batch are recorded as `CaseLifecycleStatus.NOT_ATTEMPTED` with category `UNATTEMPTED_CASE`.

### Defect 6: Independent Per-Process Budget Exhaustion (Campaign Guard)
- **Symptom:** Each proposed command ran as an independent process with `--max-cost-usd 0.05`. Running three commands permitted an aggregate exposure of $0.15, lacking a shared cross-process campaign ceiling or candidate restriction.
- **Root Cause:** Local memory-only or per-run ledger budgeting without cross-process campaign coordination.
- **Resolution:**
  - Implemented `CampaignBudgetGuard` with shared SQLite table `llm_campaign_ledger`.
  - Campaign ID persistence across multiple process invocations.
  - Restricted strictly to the exact 3 approved candidates: `t1_c5` (Gemini), `t1_c3` (Groq), `t2_c2` (Cohere).
  - Hard campaign caps:
    - Max 10 requests per candidate.
    - Max 30 requests total across campaign.
    - Aggregate commercial-equivalent spend ceiling ($0.15 default).
    - Aggregate billable spend ceiling ($0.05 default).
    - Awareness of `UNCERTAIN` liabilities holding reservation liability.

### Defect 7: Report Accounting Discrepancies
- **Symptom:** CSV and Markdown reports computed `bill_cost` dynamically based on provenance strings instead of using recorded accounting values.
- **Root Cause:** Divergent field serialization between JSON and CSV/Markdown exporters.
- **Resolution:**
  - Updated `S3BenchmarkReportGenerator` to export recorded `billable_cost_usd`, `commercial_cost_usd`, and `lifecycle_status`.
  - Added full parity tests guaranteeing matching numbers across JSON, CSV, and Markdown.

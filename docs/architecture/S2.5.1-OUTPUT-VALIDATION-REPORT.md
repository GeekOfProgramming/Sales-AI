## 1. Executive Summary

SalesAI S2.5.1 corrects eight independently reproduced integrity and safety defects (B1–B8) in the S2.5 output validation layer. In accordance with the corrective architecture specification (`docs/architecture/SALESAI-S2.5.1-OUTPUT-VALIDATION-INTEGRITY-HARDENING.md`):

1. **B1 (Fabricated Evidence Rejection):** Model outputs citing non-empty `evidence_refs` without an explicit, authoritative approved evidence set fail closed with `EVIDENCE_APPROVED_SET_REQUIRED`.
2. **B2 (Evidence Allowlist Authority):** The caller-supplied `approved_evidence_ids` argument is authoritative. Request metadata cannot broaden, override, or union untrusted IDs into the trusted allowlist.
3. **B3 (Local Opt-Out Hard Precedence):** Verified local opt-out / suppression signals strictly override **every** conflicting model classification (including `not_now`, `not_interested`, `unknown`, `auto_reply`, `bounce`, and `meeting_proposed`), setting `effective_local_disposition="unsubscribe"`, preventing unauthorized follow-ups, and failing closed.
4. **B4 (Local Bounce & Suppression Precedence):** Local bounce signals (`is_bounce_detected`) and suppression signals (`is_suppressed`) act as distinct authoritative local signals, blocking positive interest and meeting classifications (`BOUNCE_OVERRIDE_PREVENTED` / `SUPPRESSION_OVERRIDE_PREVENTED`), with deterministic signal precedence: 1. Opt-out -> 2. Bounce -> 3. Suppression.
5. **B5 (Pinned Model & Provider Identity):** Requests lacking a pinned, approved provider (`MISSING_APPROVED_PROVIDER_IDENTITY`) or model (`MISSING_APPROVED_MODEL_IDENTITY`) fail closed immediately.
6. **B6 (Subtask Integrity & Non-Website Injection Defense):** Request metadata declaring a subtask that conflicts with validator arguments triggers `IDENTITY_MISMATCH_SUBTASK`. Subtask parameters on non-website tasks fail closed.
7. **B7 (Sanitized Diagnostics & Zero Leaks):** Schema-extra fields and validation failures never reflect attacker-controlled key names, tokens, or PII into failure reasons, `safe_log_dict()`, `__repr__`, or repair proposals. Emits generic, sanitized `SCHEMA_EXTRA_FIELD` and enforces strict uppercase alphanumeric bounding `^[A-Z0-9_]{1,64}$`.
8. **B8 (Strict Primitive Types):** Enforces `strict=True` across task output schemas, strictly rejecting string-to-number coercions (e.g. string `"0.98"` in confidence, `"10"` in query priority) while accepting valid JSON numbers.

## 6. Security and Architectural Invariants Maintained

1. **Zero Operational Authority for LLM Outputs:** LLM outputs cannot send emails, confirm appointments, alter budgets, or mutate database state.
2. **Deterministic Offline Execution:** All Gateway validation tests execute completely offline without network IO, API tokens, or model downloads.
3. **No Automatic Retries or Escalation:** Validation failures do not trigger retries or tier escalation.
4. **Scrubbed Audit Logging:** Personal data, email addresses, secrets, and raw model outputs are never printed in string representations or diagnostic logs.
5. **No Production Bypass:** Operator approvals in S2.3.1 and downstream safety gates remain fully enforced.

---

## 7. Remaining Limitations & Boundaries Before S2.6

- **No Live API Dispatch:** Gateway remains disabled by default (`LLM_GATEWAY_ENABLED=false`).
- **Offline Repair Proposals Only:** Repair proposals remain purely advisory plans (`dispatch_allowed=False`). Live repair execution requires S2.6 budget, retry, and concurrency controls.
- **Operator Session Authentication:** `approved_by` operator tokens are structural identity markers; cryptographic session authentication is deferred to S2.7.

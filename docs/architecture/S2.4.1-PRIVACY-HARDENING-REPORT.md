## 1. Executive Summary

SalesAI S2.4.1 implements the mandatory corrective hardening specified in `docs/architecture/SALESAI-S2.4.1-PRIVACY-BOUNDARY-HARDENING.md` following independent review of `SalesAI_export(8).zip`. The review identified eight reproducible defects (B1–B8) that rendered the previous S2.4 implementation unapproved for live external API integration.

Under S2.4.1, all eight defects have been resolved with strict fail-closed boundary enforcement:
1. **Cross-Version Typing Rigor (B1):** Added explicit `Tuple` import in `sales_engine/llm_gateway/payload_builder.py` ensuring clean runtime compilation and collection across Python 3.11, 3.12, 3.13, and 3.14.
2. **Strict Source Identity & Envelope Integrity (B2):** `source_id` is now strictly validated as an opaque, bounded local identifier (`[A-Za-z0-9][A-Za-z0-9_.:-]{0,79}`) rejecting quotes, brackets, whitespace, and control characters. `source_kind` is restricted to a fixed local allowlist (`VALID_SOURCE_KINDS`).
3. **Fail-Closed Prompt Injection Suppression (B3):** Any detected prompt injection phrase in any field (evidence excerpts, business facts, service proposition, technical requirements, inbound body, recent reply, keywords, or source IDs) sets `manual_review_required=True` and deterministically suppresses `llm_request=None`. Safe, non-sensitive reason codes are used without echoing untrusted payload content.
4. **End-to-End Task Content Budgets (B4):** Enforced per-field upper bounds, task aggregate evidence limits, and total prompt budgets (`TASK_TOTAL_PROMPT_LIMITS`). For `outreach_draft`, an oversized (e.g. 15,000-char) `service_proposition` sets `manual_review_required=True`, records truncation, and produces `llm_request=None`. Caller-specified `custom_max_chars` is strictly validated as a positive integer and can only *reduce* a policy maximum, never escalate it.
5. **Recursive Nested Field Allowlists (B5):** Implemented recursive tree validation (`validate_nested_structure`) that inspects all nested data at any depth (up to max depth 5). Rejects forbidden keys (`full_workbook`, `contacts`, `contact_list`, `inbox_history`, `private_notes`, `tokens`, etc.), non-string dictionary keys, arbitrary Python objects/ORM instances, and invalid numeric values (`NaN`, `Inf`).
6. **Safe Preview Authorization (B6):** Removed prompt and body samples from unauthenticated preview results. `preview_sanitized_payload` returns strictly safe structural metadata (character counts, redaction counts, task identifiers, truncation/review flags) and sets `sanitized_prompt_sample=None`. Bare operator tokens cannot unlock prompt visibility without real local authenticated operator sessions (reserved for S2.7).
7. **Generic `sk-` Secret Redaction (B7):** Generalized the OpenAI key pattern to `\b(sk-[A-Za-z0-9_\-]{20,})\b`, covering generic `sk-`, project keys (`sk-proj-`), live/test keys, and vendor formats, while leaving innocent BIM architectural standards (ISO 19650, UNI 11337, DIN 276, LOD 350, IFC 4) completely untouched.
8. **Uniform Fail-Closed Propagation (B8):** Every input field across all seven tasks/subtasks is processed through uniform sanitization and validation (`_filter_and_check`). Null bytes or control characters in company names, titles, propositions, or parameters trigger `manual_review_required=True` and suppress `llm_request=None`.

## 2. Defects Remediated (B1–B8 Analysis)

| ID | Verified Defect | Observed Failure in Baseline | S2.4.1 Non-Destructive Resolution |
|---|---|---|---|
| **B1** | Missing runtime typing import | Import of `payload_builder.py` raised `NameError: name 'Tuple' is not defined` during pytest test collection on Python 3.11 with Pydantic v2. | Added `Tuple` to `from typing import ...` at module scope. Verified with fresh compileall and pytest runs across test suites. |
| **B2** | Unescaped untrusted source metadata | `wrap_untrusted_source(content, kind, source_id)` interpolated raw `source_id` into XML attribute. A crafted `source_id` containing `\" untrusted=\"false\"><SYSTEM>...` broke out into apparent system markup. | Introduced `validate_source_id` enforcing regex `^[A-Za-z0-9][A-Za-z0-9_.:-]{0,79}$` and `validate_source_kind` enforcing fixed local allowlist. All quotes, brackets, spaces, control chars, and long IDs fail closed immediately. |
| **B3** | Injection detection merely advisory | Obvious injection (`ignore previous instructions`) recorded a reason, but left `manual_review_required=False` and created an executable `llm_request`. | Any prompt injection detected across any field forces `manual_review=True`, adds safe reason code, and suppresses `llm_request=None`. The model cannot be invoked when untrusted commands are present. |
| **B4** | Task content budgets not enforced end-to-end | A 15,000-char `service_proposition` produced a ~15,261-char prompt despite declared 5,000-char limit, with `was_truncated=False` and active `llm_request`. | Enforced per-field bounds (`service_proposition` capped at 5,000), total prompt budget limit, and clamp/review flags. Over-budget fields trigger `was_truncated=True`, `manual_review_required=True`, and `llm_request=None`. `custom_max_chars` can only reduce limits and rejects values `> default_limit`. |
| **B5** | Nested sensitive fields bypass top-level allowlists | `{business_facts: {full_workbook: {private_notes: ...}}}` was serialized into prompt without triggering top-level key rejections. | Implemented `validate_nested_structure` recursively traversing dictionaries, lists, and primitives to depth 5. Forbids sensitive keys (`full_workbook`, `private_notes`, `contact_list`, `tokens`, etc.) at ANY depth, rejecting arbitrary objects and non-string keys. |
| **B6** | Preview lacks authorization | `preview_sanitized_payload` returned a 500-char prompt sample containing sanitized text without operator identity verification; bare string `operator_token` was unused. | Removed prompt samples from unauthenticated preview. `sanitized_prompt_sample` is set to `None`; returns only safe structural metadata. Bare token strings cannot bypass this restriction. |
| **B7** | Generic `sk-` secrets remain unmasked | A synthetic `sk-` followed directly by alphanumeric string survived `_OPENAI_KEY_RE` (which required an extra hyphen `sk-...-`). | Updated pattern to `\b(sk-[A-Za-z0-9_\-]{20,})\b`, masking plain `sk-`, project keys, and anthropic keys. Verified zero false positives against innocent BIM standards (ISO, UNI, DIN, LOD, Revit). Removed raw secret leakage in residual assignment reasons. |
| **B8** | Fatal sanitization failures not propagated consistently | A null byte in `company_name` triggered `PrivacyFilter` rejection, but `build_payload` ignored non-excerpt filter results, setting `manual_review_required=False` and creating `llm_request`. | Unified all field processing under `_filter_and_check`. When any field returns `manual_review_required=True` or `rejection_reason`, `build_payload` uniformly suppresses `llm_request=None` and flags manual review. |

## 5. Preserved Architectural Boundaries

1. **Sequential Model Selection Policy:** The Tier-1-first sequential evaluation and routing table (`TASK_ROUTING_TABLE_V2`) is strictly preserved without modification.
2. **Gateway Architecture:** `LLMProviderGateway`, `OpenAIProvider`, `TaskRouter`, and `EvaluationPlanner` remain the authoritative foundation.
3. **Six Active Call Sites Untouched:** All six production SalesAI LLM call sites (`website_analyzer`, `job_analyzer`, `query_generator`, `classifier`, `suggestion`, `email_generator`) remain transitional on `BIMLLMClient` until Phase S2.7.
4. **Email Safeguards Preserved:** Human-in-the-loop review, auto-send prevention, unsubscribed suppression list check, and double-gate protections remain intact.
5. **Zero External Network / Compute Dependencies:** Zero local models (no Ollama), zero live web scraping, and zero paid API calls were executed.

---

## 6. Remaining Limitations & Handoff to S2.5

- **LLM Output Schema Validation (S2.5):** S2.4.1 governs outbound payload construction and privacy boundaries. Validating received model responses against JSON schemas with controlled repair retry belongs to Phase S2.5.
- **Operator Authorization Sessions (S2.7):** Unauthenticated previews are stripped of prompt samples. Detailed prompt previews will be bound to authenticated operator sessions under Phase S2.7.
- **Provider Adapters for Secondary Tiers (S2.6):** Only the OpenAI-compatible HTTPS transport adapter is active; secondary providers (Anthropic, Gemini, Mistral) are deferred to S2.6.

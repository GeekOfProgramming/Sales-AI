## 3. Detailed Specification & Guardrail Implementation

### 3.1 Canonical Request (`LLMRequest`)
- **Strict Size Bounds:** `prompt` (1..100,000 chars), `system_prompt` (max 50,000 chars), `task_id` (1..64 chars).
- **Numerical Guards:** `temperature` bounded to `[0.0, 1.0]` with finite validation (rejects `NaN` and `Inf`); `timeout_seconds` bounded to `(0.0, 300.0]`; `max_output_tokens` bounded to `(0, 32768]`.
- **Correlation Tracking:** `request_id` defaults to opaque unique string (`req_<12 hex chars>`); zero PII, email, or URL identifiers.
- **Schema Compatibility:** Supports both `response_schema` and `schema` alias without colliding with Pydantic internal methods.
- **Metadata Protection:** Custom validator prohibits sensitive keys (e.g., `api_key`, `token`, `password`, `email`).
- **PII-Scrubbed String Representation:** `__repr__` displays prompt character length rather than raw text, preventing customer data leakage in debug logs.

### 3.2 Canonical Response (`LLMResponse`)
- **Factual Integrity:** Unmeasured metrics (`input_tokens`, `output_tokens`, `cost_usd`, `latency_ms`) default strictly to `None`, **never** fabricated as zero or synthetic estimates.
- **Non-Negative Constraints:** Token counts, costs, and latencies are strictly validated to be non-negative finite real numbers.
- **Structured Output Separation:** `parsed_json` is populated only when valid JSON was parsed from model output.

### 3.3 Error Taxonomy & Security
Standardized exception hierarchy inheriting from `LLMError`:
- `LLMNotConfiguredError` (code: `"NOT_CONFIGURED"`, retryable: `False`)
- `LLMAuthenticationError` (code: `"AUTH_ERROR"`, retryable: `False`)
- `LLMTimeoutError` (code: `"TIMEOUT"`, retryable: `True`)
- `LLMRateLimitError` (code: `"RATE_LIMIT"`, retryable: `True`)
- `LLMQuotaExceededError` (code: `"QUOTA_EXCEEDED"`, retryable: `False`)
- `LLMBudgetExceededError` (code: `"BUDGET_EXCEEDED"`, retryable: `False`)
- `LLMInvalidSchemaError` (code: `"INVALID_SCHEMA"`, retryable: `False`)
- `LLMProviderUnavailableError` (code: `"PROVIDER_UNAVAILABLE"`, retryable: `True`)
*Security Guarantee:* Exception formatting masks sensitive tokens and includes only provider ID, task ID, and high-level error descriptions.

### 3.4 Fail-Closed Governance & Isolation
- The `LLMProviderGateway` instantiates with `enabled=False` by default. Any attempt to invoke `generate()` or `generate_async()` without explicitly enabling the gateway raises `LLMNotConfiguredError`.
- No silent fallback to Ollama, no automatic fallback to arbitrary external models, and no automatic tier escalation.
- Zero commercial SDK imports (`openai`, `anthropic`, `google.generativeai`) at module load.

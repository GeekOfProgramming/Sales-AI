## 1. Executive Summary

SalesAI S3.4 expands the SalesAI multi-provider benchmark and inference architecture to support **seven canonical provider integrations**:
`openai`, `gemini`, `groq`, `openrouter`, `cohere`, `nvidia`, and `cloudflare` (with historical `xai` retained but locked).

### Key Accomplishments in S3.4:
1. **Preserved S3.3 Baseline & Candidate Bindings**: Historical bindings `t1_c1` through `t1_c4` remain untouched. New providers are mapped to Tier 2 candidate slots (`t2_c1` through `t2_c4`) with zero silent candidate collisions. Historical `xai` remains strictly disabled and excluded from active routing.
2. **Provider-Specific API Contract Support**:
   - **Cohere**: Built a dedicated `CohereProvider` implementing Cohere's native v2 Chat API (`/v2/chat`), message content block parsing (`content[].text`), and token usage extraction (`tokens.input_tokens` / `tokens.output_tokens`).
   - **Cloudflare Workers AI**: Built a dedicated `CloudflareProvider` enforcing strict 32-hex Account ID resolution (`CLOUDFLARE_ACCOUNT_ID` or DPAPI secrets) and routing to `https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/v1`.
   - **OpenRouter / NVIDIA NIM**: Integrated with custom header injection (`HTTP-Referer`, `X-Title`) and catalog filtering.
3. **Rigorous Free-First & Billing Classification**:
   - `VERIFIED_FREE_TIER`: `gemini` (`gemini-2.5-flash-lite`), `groq` (`openai/gpt-oss-20b`), `openrouter` (only models bearing the explicit `:free` suffix, e.g. `meta-llama/llama-3.3-70b-instruct:free`).
   - `VERIFIED_PAID`: `openai` (`gpt-6-luna`), `openrouter` (standard paid models).
   - `UNKNOWN`: `cohere` (Trial key evaluation terms/rate limits), `nvidia` (evaluation credits expire), `cloudflare` (10,000 neurons/day allocation, overages charged on paid plans), `xai` (locked).
   - Fail closed: Models classified as `UNKNOWN` or `VERIFIED_PAID` are unconditionally rejected when `--free-only` is asserted.
4. **Deterministic Root Cause Investigation of OpenAI `web_a_01` Failure**:
   Reproduced and resolved the exact S3.2 smoke test anomaly (`s3_bench_187335fa5d`) across 7 diagnostic dimensions in a dedicated regression test (`test_openai_web_a_01_smoke_failure_deterministic_reproducer`).
5. **Controlled Operator Inference Readiness**:
   Designed strict, single-request operator-controlled smoke workflows with dry-run defaults, non-chargeable metadata probing, and persistent SQLite reservation audits.

**Zero real commercial LLM generation requests were dispatched during development.** All verifications were executed offline using `httpx.MockTransport`, deterministic evaluation suites, and offline regression harnesses.

## 3. Detailed Root Cause Analysis: OpenAI `web_a_01` Smoke Failure

During the S3.2 live smoke test (`s3_bench_187335fa5d`), OpenAI `gpt-6-luna` completed the HTTP transport roundtrip in 7,942 ms, emitting 369 output tokens. However, the benchmark reported overall failure.

Our deterministic offline investigation analyzed the exact raw payload and scoring pipeline against the 7 diagnostic requirements:

### Diagnostic Findings:

1. **Syntactic JSON Validity**:
   - **Finding**: The model produced **100% syntactically valid JSON**. The payload parsed cleanly via `json.loads(response.content)`. There were no truncated tokens, trailing commas, or syntax errors.
2. **Schema Enum Violation (`offerings.status`)**:
   - **Finding**: The model emitted `"status": "available"` for the first offering (`MEP Coordination`).
   - The canonical Pydantic schema `OfferingItem` strictly specifies:
     ```python
     status: Literal["active", "in_development", "coming_soon", "cta"]
     ```
   - `"available"` is outside this closed set.
3. **Parser Discarding Valid Fields upon Schema Failure**:
   - **Finding**: Pydantic's strict model validation caught the enum mismatch and raised a `ValidationError`. Consequently, `LLMOutputValidator` set `val_result.validated_data = None`.
   - All factual fields extracted by the model (`company_name`, `company_summary`, `technologies`, `evidence_refs`) were present in the raw JSON but unavailable in `validated_data`.
4. **Evidence Reference Retention**:
   - **Finding**: The raw payload contained `"evidence_refs": ["EV_01"]`. In the S3.1 evaluator, because `validated_data` was `None`, citation checks attempted to read `validated_data.get("evidence_refs", [])`, which defaulted to empty, falsely reporting `MISSING_EVIDENCE_REFS`.
   - Extracting evidence references from raw JSON preserves citation validity even when the formal schema fails.
5. **Downstream Semantic Scoring Fallacy**:
   - **Finding**: In S3.1, `GroundTruthEvaluator` evaluated company name accuracy by comparing expected `"Milano MEP Ingegneria S.r.l."` against `val_data.get("company_name", "")`. Since `val_data` was `None`, it compared against `""` and reported a false `GROUND_TRUTH_COMPANY_MISMATCH`.
   - The S3.2 fix correctly isolates this: when schema validation fails, semantic comparison is marked `SEMANTIC_NOT_EVALUATED_INVALID_SCHEMA` rather than fabricating a factual mismatch.
6. **Request-Side Structured Output Enforcement**:
   - **Finding**: When OpenAI's `response_format={"type": "json_schema", "json_schema": {"strict": True, ...}}` or explicit schema definition is passed at request time, the model is grammatically constrained to valid enum values (`"active"`), preventing enum drift.
7. **Usability of Repair Proposals**:
   - **Finding**: `LLMOutputValidator.generate_repair_proposal` can suggest repairing `"available"` to `"active"` for operator review. However, **automatic unmetered paid retries remain strictly prohibited** to prevent unexpected billing.

## 4. Technical Architecture Enhancements

### A. Modular Provider Adapters
- `OpenAIProvider`: Enhanced to support custom HTTP headers (such as `HTTP-Referer` and `X-Title` for OpenRouter) and generalized model discovery across OpenAI, Gemini, Groq, OpenRouter, and NVIDIA NIM.
- `CohereProvider`: Custom adapter for Cohere v2 Chat API:
  - Formats messages with `role` and `content`.
  - Serializes `response_format={"type": "json_object"}`.
  - Extracts text from `message.content[0].text`.
  - Normalizes token counts from `response.body["usage"]["tokens"]`.
  - Maps Cohere error payloads to canonical SalesAI exceptions (`LLMAuthenticationError`, `LLMRateLimitError`, etc.).
- `CloudflareProvider`: Custom adapter for Cloudflare Workers AI:
  - Validates and enforces 32-character hexadecimal Account ID.
  - Builds account-scoped URL: `https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/v1`.
  - Probes catalog via `/ai/models/search?per_page=20`.

### B. Catalog & Candidate Management
- Retains S3.3 candidates: `t1_c1` (OpenAI), `t1_c2` (Gemini), `t1_c3` (Groq), `t1_c4` (xAI).
- Onboards Tier 2 candidates:
  - `t2_c1`: OpenRouter (`meta-llama/llama-3.3-70b-instruct:free`)
  - `t2_c2`: Cohere (`command-r-08-2024`)
  - `t2_c3`: NVIDIA NIM (`meta/llama-3.3-70b-instruct`)
  - `t2_c4`: Cloudflare Workers AI (`@cf/meta/llama-3.1-8b-instruct`)
- Strict separation between catalog discovery and production model routing: all benchmark candidates are marked `SMOKE_ONLY / NOT MODEL-QUALIFIED`.

### C. Budget Ledger Integrity & Missing Usage Safeguards
- Every live request creates a persistent preflight reservation in SQLite (`llm_reservations`).
- For `VERIFIED_FREE_TIER` models, the reservation reconciles to `$0.000000` with provenance `VERIFIED_FREE_TIER`.
- If a provider response omits token usage fields, the system raises `LLMUncertainUsageError`, records `status = 'UNCERTAIN'` in SQLite, and retains the full projected liability against budget ceilings. It is never marked `$0.00`.

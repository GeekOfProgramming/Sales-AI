# SalesAI S3.2 — Operator Runbook: Controlled Live Smoke Pilot

**Target Audience:** Human Operator / System Administrator  
**Scope:** Controlled execution of the first single-case live commercial LLM benchmark smoke test.  
**Precondition:** Requires separate human approval and operational authorization. Live execution is disabled by default.

---

## 1. Safety Principles & Invariants

1. **Two-Key Authorization Required:**
   Live benchmark dispatch requires both `--live` AND `--confirm-paid`. Omitting `--confirm-paid` causes the runner to fail closed immediately without dispatching any HTTP traffic.

2. **Zero Commercial Dispatches by Default:**
   No automated background tasks or standard test runs ever make external HTTP calls or touch paid APIs. All automated CI/CD and developer tests run strictly offline.

3. **No Mock Providers or Fictitious Pricing in Live Mode:**
   Live mode strictly refuses mock providers (`openai_compatible_mock`) or mock pricing tables (`pricing.mock.internal`). The only candidate enabled for S3.2 live smoke is verified Tier-1 slot `t1_c1` (`gpt-6-luna` via real `OpenAIProvider` HTTPS adapter with official rates: `$0.10` input / `$0.50` output per 1M tokens, effective 2026-10-22). All other 15 candidate slots are disabled.

4. **Hard Cost & Request Limits Strictly Enforced:**
   Every live run must specify `--max-requests` (positive integer 1..20, default 1) and `--max-cost-usd` (positive finite float 0..1.00, default 0.05). In preflight, if estimated or cumulative spend exceeds this threshold, or if the request ceiling is reached, dispatch is blocked immediately.

5. **Single-Case Scope for S3.2 Smoke:**
   Live smoke allows strictly:
   - Exactly ONE task (`website_extraction:pass_a`)
   - Exactly ONE candidate (`t1_c1`)
   - Exactly ONE fixture case (`--max-cases 1`)
   - Exactly ONE paid request (`--max-requests 1`)
   - Zero automatic retries, tool calls, provider switching, or tier escalation.

6. **Persistent, Locally Excluded SQLite Ledger:**
   In live mode, in-memory SQLite (`:memory:`) is strictly prohibited. Runs must record reservations and reconciliations into a persistent local database (`data/benchmark_budget.db`), which is excluded from Git via `.gitignore`.

7. **Zero Operational Call Site Modification:**
   Benchmark evaluations are strictly independent. A passing benchmark run **DOES NOT** update routing tables, modify the six operational LLM call sites, or authorize production traffic. Status remains `SMOKE_ONLY / NOT MODEL-QUALIFIED`.

8. **Provider Dashboard Cap vs. Application Budget Cap:**
   - **Provider Dashboard Cap:** Set directly in the OpenAI API billing platform (e.g. hard monthly spending limit of $5.00). This is the external failsafe.
   - **Application Budget Cap (`--max-cost-usd`):** Enforced locally by SalesAI SQLite preflight reservation before the socket opens. Both guards operate in defense-in-depth.

## 3. Minimal 1-Case Pilot Execution

Execute the following exact command in PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_external_llm.py `
    --live `
    --confirm-paid `
    --task website_extraction:pass_a `
    --candidate t1_c1 `
    --max-cases 1 `
    --max-requests 1 `
    --max-cost-usd 0.05 `
    --db-path data/benchmark_budget.db `
    --output-dir reports/benchmark/pilot
```

### Expected Output Behavior:
1. **Preflight Validation:** Runner verifies `--live` and `--confirm-paid` are both present.
2. **Pricing Source Check:** Asserts pricing is verified (`provider_direct_verified`) and candidate `t1_c1` is wired to real `OpenAIProvider`.
3. **Budget Reservation:** Preflight atomically reserves maximum projected cost in `data/benchmark_budget.db` (`llm_reservations` table).
4. **Dispatched Request:** Dispatches exactly 1 prompt to OpenAI HTTPS API (`https://api.openai.com/v1/chat/completions`).
5. **Output Evaluation:** Scores schema validity, factual ground truth, evidence grounding, and safety compliance offline.
6. **Reconciliation:** Actual tokens reported by API are recorded and reconciled in `data/benchmark_budget.db`.
7. **Report Generation:** Produces `benchmark_results_<run_id>.json`, `benchmark_cases_<run_id>.csv`, and `BENCHMARK_REPORT_<run_id>.md`.
8. **Smoke Test Guard:** Candidate status is marked `SMOKE_ONLY`. Candidate is **NOT** proposed as a production winner (`is_production_approved: False`).

## 4. Post-Flight Audit & Verification

Immediately following completion:

### 1. Verify Report Artifacts
Inspect the generated markdown report:
```powershell
Get-Content (Get-ChildItem reports/benchmark/pilot/BENCHMARK_REPORT_*.md | Select-Object -Last 1).FullName
```
Confirm:
- Total cases evaluated: 1
- Total cost measured: <= $0.05 (typically ~$0.0001 for 1 short case)
- Candidate status: `SMOKE_ONLY`
- Zero hard safety violations detected
- Pricing source mode: `provider_direct_verified`

### 2. Verify Persistent Ledger Records
Query the actual SQLite database (`data/benchmark_budget.db`) using the correct schema (`llm_reservations`):
```powershell
.\.venv\Scripts\python.exe -c "import sqlite3; conn = sqlite3.connect('data/benchmark_budget.db'); rows = conn.execute('SELECT reservation_id, request_id, model, status, reserved_usd, final_cost_usd, created_at FROM llm_reservations ORDER BY created_at DESC LIMIT 5').fetchall(); print('\n'.join(str(r) for r in rows))"
```
Confirm:
- Exactly 1 record created for this run.
- Status is `RECONCILED` (or `UNCERTAIN` if connection timed out).
- `final_cost_usd` is positive and matches reported tokens.

### 3. Verify Provider Console
Log into `https://platform.openai.com/usage` and confirm:
- Exactly 1 request logged for `gpt-6-luna`.
- Token counts match local ledger reported tokens (`reported_input_tokens`, `reported_output_tokens`).

## 6. Rollback & Abort Procedures

If the live smoke test fails, encounters an error, or hangs:

1. **Immediate Cancellation:**
   Press `Ctrl+C` in the running PowerShell terminal. The runtime budget guard ensures in-flight reservations are preserved as `UNCERTAIN` rather than silently erased as free.
2. **Key Revocation:**
   Immediately delete or disable the API key in the OpenAI platform console if unexpected behavior occurs.
3. **Clean Audit Directory:**
   Remove pilot report logs if needed:
   ```powershell
   Remove-Item -Recurse -Force reports/benchmark/pilot
   ```
4. **Operational Call Site Integrity:**
   No operational code changes were made; the six SalesAI core LLM sites remain 100% untouched and operational.

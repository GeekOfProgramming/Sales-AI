## 2. Root Cause Analysis of Cohere Schema Failure

Inspection of `sales_engine/llm_gateway/providers/cohere_provider.py`, `output_schemas.py`, `output_validation.py`, and `fixtures_s3.py` revealed:

1. **Adapter Request Configuration (Primary Root Cause)**:
   - In S3.5.4B, the request was dispatched with generic JSON object mode: `response_format={"type": "json_object"}`.
   - Cohere Command R 08-2024 returned syntactically valid JSON. However, because no schema was supplied to the model, the model generated `evidence_refs` as either an invalid type or an unstructured string, rather than an array of strings.
   - The downstream Pydantic validator `WebsitePassAOutput` strictly requires `evidence_refs: List[str]`. This triggered `ValidationError` on `evidence_refs`, resulting in `SCHEMA_TYPE_ERROR_EVIDENCE_REFS`.

2. **Inadequate Schema Prompt Instructions**:
   - `PASS_A_SCHEMA_SPEC` loosely specified `evidence_refs [str citing source IDs]`, which LLMs frequently interpret as a scalar citation string (e.g., `"EV_01"`) rather than a JSON array `["EV_01"]`.

3. **No False Syntactic Success Reporting**:
   - The system correctly recorded `syntactic_valid=False`, `overall_pass=False`, and `failure_categories=["SCHEMA_TYPE_ERROR_EVIDENCE_REFS"]`.
   - The system correctly halted before semantic and evidence evaluation without mislabeling schema-invalid output as valid.

## 3. Provider-Side Cohere JSON Schema Implementation

Cohere natively supports structured outputs for `command-r-08-2024` via:
```json
{
  "response_format": {
    "type": "json_object",
    "schema": {
      "type": "object",
      "properties": { ... },
      "required": [ ... ]
    }
  }
}
```

### 3.1 Recursive `$defs` / `$ref` Inlining (`to_cohere_json_schema`)
Cohere's JSON Schema validator requires self-contained schemas and fails on unresolved `$defs` or complex JSON Schema keywords. In `sales_engine/llm_gateway/output_schemas.py`:
- Implemented `to_cohere_json_schema(model_cls_or_dict)`:
  - Generates standard Pydantic JSON Schema.
  - Extracts and recursively inlines all `$defs` definitions into `$ref` target sites, removing `$defs`.
  - Strips unsupported validation keywords: `minLength`, `maxLength`, `minItems`, `maxItems`, `minimum`, `maximum`, `pattern`, `title`, and root descriptions.
  - Rejects incompatible schema composition keywords (`allOf`, `oneOf`, `not`) with fail-closed `LLMInvalidSchemaError`.
  - Explicitly ensures `evidence_refs` is defined as `{"type": "array", "items": {"type": "string"}}`.
  - Preserves exact offering status enum values: `["active", "in_development", "coming_soon", "cta"]`.

### 3.2 Gateway Adapter Enforcement & Silent Downgrade Prevention
In `sales_engine/llm_gateway/providers/cohere_provider.py`:
- In `_build_payload()`:
  - If `request.response_schema` contains `properties` (a structured schema request):
    - Verifies candidate model capability `supports_json_schema`.
    - If `supports_json_schema` is false, raises `LLMInvalidSchemaError` with explicit message: `"refusing silent downgrade to JSON Object Mode"`.
    - Converts schema using `to_cohere_json_schema()` and wraps as `payload["response_format"] = {"type": "json_object", "schema": cohere_schema}`.
  - If `response_schema={"type": "object"}` without properties:
    - Emits basic `payload["response_format"] = {"type": "json_object"}`.
- In `_parse_response_body()`:
  - Captures `usage.billed_units` in `raw_metadata["billed_units"]`.
  - Uses `billed_units` if standard token counts are missing from provider response.

## 6. Correct Trial Rate-Limit Reporting

Official Cohere Command R Trial documentation and account headers were separated into distinct operational concepts:
1. **Documented Model Limits**: Cohere documents **20 requests/minute** for Command R Trial Chat and a **1,000 monthly Trial calls** limit.
2. **Account Response Headers**: The trial header `x-trial-endpoint-call-limit: 100` represents an account-level endpoint limit, NOT 100 chat requests per minute.
3. **Safety Gate**: `--require-cohere-trial` retains strict fail-closed behavior, requiring presence of authenticated trial headers (`x-trial-endpoint-call-limit` or `x-trial-endpoint-call-remaining`) before dispatch.

## 7. Resolution of Archive Checksum Paradox

### 7.1 Defect Analysis
In S3.5.4B, calculating a ZIP archive's SHA-256 and embedding that hash within a report stored inside the archive created a circular self-reference: modifying the file altered the archive, changing the final SHA-256 hash.

### 7.2 Implemented Sidecar Architecture
Updated `scripts/rebuild_zip.py`:
1. Source tree is fully finalized and all documents are written.
2. `SalesAI_export.zip` is created excluding temporary files, `.sha256` sidecars, `*.db`, caches, and credentials.
3. The SHA-256 checksum is computed on the finalized ZIP file and written to external sidecar file:
   `C:\Sales-AI\SalesAI_export.zip.sha256`
4. The sidecar resides alongside the ZIP, never inside the archive.

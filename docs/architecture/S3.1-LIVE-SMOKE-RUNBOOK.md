# SalesAI S3.1 — Operator Runbook: Controlled Live Smoke Pilot

**Target Audience:** Human Operator / System Administrator  
**Scope:** Controlled execution of the first single-case live commercial LLM benchmark test.  
**Precondition:** Requires separate human approval and operational authorization. Live execution is disabled by default.

---

## 1. Safety Principles & Invariants

1. **Two-Key Authorization Required:**
   Live benchmark dispatch requires both `--live` AND `--confirm-paid`. Omitting `--confirm-paid` causes the runner to fail closed immediately without dispatching any HTTP traffic.

2. **Zero Commercial Dispatches by Default:**
   No automated background tasks or standard test runs ever make external HTTP calls or touch paid APIs.

3. **No Mock Pricing in Live Mode:**
   Live mode strictly refuses candidates configured with mock or internal pricing (`pricing.mock.internal`). Verified pricing tables or direct provider pricing are mandatory.

4. **Hard Cost & Request Limits:**
   Every live run must specify `--max-requests` (ceiling: 20) and `--max-cost-usd` (ceiling: $1.00). In preflight, if estimated or cumulative spend exceeds this threshold, dispatch is blocked immediately.

5. **Zero Call Site Modification:**
   Benchmark evaluations are strictly independent. A passing benchmark run **DOES NOT** update routing tables, modify the six operational LLM call sites, or authorize production traffic.

---

## 2. Preflight Checklist

Before initiating the live smoke test, verify:

- [ ] A dedicated human operator has explicitly authorized a single-case test.
- [ ] An active provider billing account with a spending cap is configured.
- [ ] The API key is set in the runtime environment memory only and NOT committed:
  ```powershell
  # Windows PowerShell (temporary session only)
  $env:OPENAI_API_KEY = "sk-proj-..."
  ```
- [ ] Confirm no keys exist in repository files or git history.
- [ ] Verify the target directory exists and is clean:
  ```powershell
  New-Item -ItemType Directory -Force -Path "reports/benchmark/pilot"
  ```

---

## 3. Minimal 1-Case Pilot Execution

Execute the following exact command in PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_external_llm.py `
    --live `
    --confirm-paid `
    --task website_extraction:pass_a `
    --candidate t1_c1 `
    --max-cases 1 `
    --max-requests 2 `
    --max-cost-usd 0.05 `
    --output-dir reports/benchmark/pilot
```

### Expected Output Behavior:
1. **Preflight Validation:** Runner verifies `--live` and `--confirm-paid` are both present.
2. **Pricing Source Check:** Asserts pricing is verified and not mock.
3. **Budget Reservation:** Preflight reserves cost for 1 request against the SQLite ledger.
4. **Dispatched Request:** Dispatches exactly 1 prompt to the provider.
5. **Output Evaluation:** Scores schema validity, factual ground truth, evidence grounding, and safety compliance.
6. **Report Generation:** Produces `benchmark_results_<run_id>.json`, `benchmark_cases_<run_id>.csv`, and `BENCHMARK_REPORT_<run_id>.md`.
7. **Smoke Test Guard:** Flags candidate status as `SMOKE_ONLY`. Candidate is **NOT** proposed as a production winner.

---

## 4. Post-Flight Audit & Verification

Immediately following completion:

1. **Verify Report Artifacts:**
   Inspect the generated markdown report:
   ```powershell
   Get-Content (Get-ChildItem reports/benchmark/pilot/BENCHMARK_REPORT_*.md | Select-Object -Last 1).FullName
   ```
   Confirm:
   - Total cases evaluated: 1
   - Total cost measured: <= $0.05
   - Candidate status: `SMOKE_ONLY`
   - Zero hard safety violations detected

2. **Verify Ledger Record:**
   Confirm SQLite ledger registered 1 reservation and 1 reconciliation:
   ```powershell
   .\.venv\Scripts\python.exe -c "import sqlite3; conn = sqlite3.connect('sales_engine/llm_gateway/budget_ledger.db'); print(conn.execute('SELECT request_id, model, status, actual_cost_usd FROM ledger_records ORDER BY timestamp DESC LIMIT 5').fetchall())"
   ```

3. **Verify Provider Dashboard:**
   Log into the provider console (e.g. platform.openai.com) and confirm actual billed usage matches the local ledger reconciliation within 1-2 cents.

## 5. Teardown & Environment Sanitization

Immediately revoke and clear the temporary API key from session memory:

```powershell
# Windows PowerShell
Remove-Item Env:\OPENAI_API_KEY
```

Verify the key is cleared:
```powershell
$env:OPENAI_API_KEY
# (Should return empty)
```

---

## 6. Rollback & Abort Procedures

If the live smoke test fails, encounters an error, or exceeds expected latency:

1. **Immediate Cancellation:**
   Press `Ctrl+C` in the running terminal. The runtime guard will cancel or mark the in-flight reservation as `UNCERTAIN` in the local ledger.
2. **Key Revocation:**
   Immediately delete the API key from the provider dashboard if compromise or unexpected loop behavior is suspected.
3. **Clean Audit Directory:**
   Remove pilot logs if they contain unredacted provider diagnostics:
   ```powershell
   Remove-Item -Recurse -Force reports/benchmark/pilot
   ```
4. **Operational Call Site Integrity:**
   No operational code changes were made; the six SalesAI core LLM sites remain 100% untouched and operational.

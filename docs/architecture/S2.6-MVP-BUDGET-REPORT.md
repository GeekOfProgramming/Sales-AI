## 1. Executive Summary

SalesAI S2.6 implements the **Minimal Budget Ledger & API Runtime Guards (MVP)** according to `docs/architecture/SALESAI-S2.6-MVP-BUDGET-AND-RUNTIME-GUARDS.md`.

In alignment with the updated development priority ("reach practical, small-scale, real-model benchmarking sooner; avoid unnecessary hardening subphases and overengineering"), S2.6 implements the core operational safeguards needed before small, explicitly authorized paid API pilots while deferring lower-risk edge cases to a documented backlog:

1. **Configurable Spending Policy (`BudgetPolicyConfig`):** Default all paid dispatch to disabled (`enabled=False`). Enforces daily (`$1.00`), monthly (`$15.00`), and per-request maximum projected spend caps (`$0.10`), request timeout, local concurrency ceiling, and per-provider rate cooldown.
2. **Local Accounting Ledger (`BudgetLedger`):** Lightweight SQLite database (`data/llm_usage.db`), excluded from Git and release ZIP packaging. Records task, subtask, provider, model, correlation ID, timestamps, actual provider-reported tokens, verified pricing version, preflight reservation amount, final calculated spend, lifecycle status (`RESERVED`, `RECONCILED`, `UNCERTAIN`, `CANCELLED`), and bounded non-sensitive failure codes. Stores **zero** raw prompts, completions, API keys, or contact data.
3. **Preflight Budget Reservation:** Before any billable request, verifies candidate pricing metadata, conservatively projects input/output token bounds, and atomically reserves funds against daily and monthly limits. If pricing is unverified or budget is exceeded, fails closed.
4. **Post-Response Reconciliation:** On response, calculates actual spend from reported token usage and verified pricing. Unmeasured or missing token counts are **never** treated as free (`$0.00`); reservations are retained against the budget and marked `UNCERTAIN` for operator review.
5. **Local Concurrency & Rate Guards (`RuntimeGuard`):** Enforces a shared local concurrency ceiling (sync and async parity) and per-provider cooldown intervals. Immediate fail-closed on first 429 (`LLMRateLimitError`) or 5xx (`LLMProviderUnavailableError`) with **zero** automatic paid retries, zero vendor switching, and zero tier escalation.
6. **Operator-Visible Overview (`BudgetSummary`):** Localhost-only, read-only summary providing daily/monthly totals, remaining spend, status breakdowns, and outstanding reservations without leaking prompts or PII.
7. **Integration Seam:** Wraps execution in `LLMProviderGateway` without modifying the six production call sites or enabling network access by default.

### 5.2 Non-Blocking Backlog Register

| ID | Category | Description | Risk Assessment | Mitigation / Plan |
|:---|:---|:---|:---|:---|
| **NB-01** | Scalability | SQLite multi-process locking under distributed workers | **Low**: SalesAI runs on a single Windows laptop on localhost with <=2 concurrent calls. | In-process threading lock and SQLite WAL mode are sufficient. Distributed DB evaluated only if multi-node architecture is ever adopted. |
| **NB-02** | Pricing Sync | Automated price catalog synchronization with upstream provider APIs | **Low**: Providers change pricing infrequently with advance notice. | Current static verified pricing in catalog with `effective_date` is safe and fail-closed. Automatic fetcher can be added in S3+. |
| **NB-03** | Token Estimation | Character-to-token divisor heuristic fine-tuning for non-Latin alphabets | **Low**: SalesAI pilot domain focuses on Italian and English architecture/BIM engineering websites. | Current conservative divisor (`3.0` chars/token) overestimates Latin tokens safely. Configurable per language if non-Latin expansion occurs. |
| **NB-04** | Sub-Budgets | Granular task-specific budget allocations (e.g., $0.20 for extraction vs $0.80 for outreach) | **Low**: Daily ($1.00) and monthly ($15.00) global caps prevent any runaway cost. | MVP per-request cap ($0.10) constrains individual tasks. Subtask allocations can be layered in future release if needed. |
| **NB-05** | Reporting Format | Exporting budget ledger to CSV or JSON formats for external accounting software | **Low**: Operator summary method (`get_budget_summary()`) and standard SQLite queries cover all local inspection needs. | Exporter utility can be added when accounting integration is specified. |
